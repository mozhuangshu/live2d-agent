# 角色制作与播放：经验教训和防回归清单

这份清单把此前原型制作、表情调试和读稿流程中可确认的经验泛化为工程检查，不公开个人原图、衍生角色、校准数据、对话或私有部署信息。区分**历史观察**、**当前实现**与**仍待验证**，避免把经验当作本项目已全部实现的能力。

## 1. 先确认交付物类型

- 整张图的浮动/缩放、局部形变预览，不等于 Cubism 模型。
- 程序化 Canvas 主持人和 `.avatar.json` 是本网页的渲染方式，不是 `.moc3`。
- 上游技能已下载、依赖可导入、源码通过语法检查，都不等于模型已构建、技能已自动发现或 VTS 已验收。
- 本仓库的真实 Live2D 路径仍未经过完整生成、Core 加载与目标 VTS 验收。报告缺什么，不能用替代预览冒充成功。

## 2. 单图眼眉修补和拆层

历史修补中，眼周暗线的主要问题是补肤取到了眉尾/眼窝暗色，加上原眼线没有遮净；早期“眉毛被压缩”的推测不足以解释最终像素现象。不要未经逐帧检查就把猜测写成根因。

- 眼睛、眉毛必须独立定义，不能把眉毛带进眼睛压缩区域。
- 补底应取干净肤色，完整遮盖旧眼线，同时保留眉形；看慢放和睁闭眼逐帧图，而不是只看静态睁眼。
- 当前离线生成器只用区域周边中位颜色估计补底，不做语义修补。照片、阴影或遮挡可能产生接缝，应检查 `calibration.png` 并手工调整 `features.*.fill`，不能宣称自动修复。
- 历史自动拆层曾把胡须当作嘴。拆层脚本退出成功不代表语义正确。先查看每层的缩略图、bbox、透明度和遮挡补全，再允许绑定；错误层应停下纠正。
- 极慢过渡中的线宽变化、缺失的隐藏区域也属于需要披露的缺陷。

## 3. 六种表情不是三个权重换标签

历史原型出现过六种表情区分不清、预设笑容眼嘴脱节、笑眼误用普通眨眼等现象。

- 自然脸要先确定：紧眉和下垂嘴角的原画，默认就可能显得严肃。
- 完整表情应设计眉、眼、脸颊、嘴角组合；对笑眼与闭眼分别验收。
- **嘴角形状与张嘴幅度分离**：表情决定 smile/frown，语音决定 aperture。微笑、大笑都应能闭嘴，普通说话不能因为张嘴就判成笑。
- 切换预设要清除旧的手动嘴值；回自然状态要清理之前的笑容/脸颊值。检查快速切换、播放结束和停止后的残留。
- 本仓库的程序化 Lumi 和单图木偶能力不同。木偶只做局部压缩/旋转和程序化嘴形，尚未实现精细笑眼重绘、上齿或脸颊联动，不可照搬更成熟角色的效果承诺。

## 4. 表情识别与角色呈现要分开验收

历史识别原型的自然校准如果只排除眨眼/张嘴，会把微笑或皱眉污染为自然基线；眉眼和嘴角的响应曲线也会造成不同步。识别的个人校准、两轮分步采样、平滑/滞后和低置信拒识，应独立设计与实测。

**当前项目采用 Agent 脚本驱动，不进行摄像头表情识别或真实情绪推断。** 认真/自然、皱眉/愤怒的分类困难不能靠演示图掩盖。数学参数测试和合成输入测试，不证明真实摄像头的识别准确度。

## 5. 语音、口型和视频

- SpeechSynthesis 不提供完整音素或合成音频振幅；中文引擎可能没有 word boundary。当前系统朗读口型是节奏估计。
- 本地音频 RMS 只能有声开口、静音闭口，不是 viseme / 音素对齐。
- 从实际语音开始事件驱动状态；测试迟到回调、暂停时结束、停止后回调、静音闭嘴、段落停顿及音频结束。
- 视频导出若按旁白音量逐帧驱动嘴巴，应检查段落边界和完整音画。仅做截图、波形或 ffprobe 检查，不等于完整旁白听审。当前仓库不提供视频导出。

## 6. 运行状态要有产物证据

“准备好”“传输中”“已启动”“已渲染”“已验收”“已交付”是不同状态。历史长流程出现过把传输当渲染、未及时发现已有产物的问题。

- 查进程、日志、产物更新时间及文件内容，不仅看启动回执。
- HTTP 202 是命令接收，`play()` 是开始播放；播放器 `ended` 才代表播放结束。
- 大任务先做最小产物验证，再估算成片体积与交付限制，避免最后才发现文件过大。
- 失败回滚、重复导入、快速重置、暂停/继续和关闭页面，都要有可见而准确的状态。

## 7. 测试证据和目标设备

为每次交付记录：源码/单元测试、合成图片 CLI、真实浏览器、真实音频、真实相机、Cubism Core、桌面 VTS、手机分别测了什么。没有测试就写未测试。

现有测试数量、参数组合数再大，也不能证明人物还原质量、实摄识别、设备音频权限或真实口型精度。当前新增测试验证文件格式、参数边界、本地生成和渲染调用；它们不是所有真人/插画的视觉质量保证。正式模型须在授权 Runtime 中验证，而不是仅验证 `.moc3` 文件存在。

## 8. 隐私、许可与第三方代码

- 本地开发授权不代表上传图片授权。云端拆层或生成需明确图片、服务与用途；本地流程失败不能静默切换服务。
- 上游 variants 可能外传图片；See-through 默认 auto 可连接外站；包装/拆层可删除目标目录；Core 自动发现可加载未知动态库。单独取得上游源码后必须审查和限制路径，不作为本项目默认自动执行步骤。
- 曾经遇到某服务访问限制不等于“已经成功拆层”。报告实际结果。
- 原图与衍生角色、SDK、模型权重和音频不自动继承项目 MIT。不要把历史人物或私人叙事复制到公开仓库。
- 新建私有输出目录，拒绝覆盖旧输出；测试使用合成素材，真实用户素材不进入公开夹具。
